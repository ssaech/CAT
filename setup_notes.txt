- The source MightLJSpeech corpus only provided `metadata.csv`, not `train_data.txt`, `dev_data.txt`, or `test_data.txt`, so we generated those split files with the patched [split_data.py](/Users/web/CAT/egs/IuMien/local/split_data.py).

- We patched [data_prep.py](/Users/web/CAT/cat/utils/data/data_prep.py) so CAT can fall back to standard WAV loading without `torchcodec`, and we forced single-worker extraction to avoid the macOS `torch_shm_manager` shared-memory failure.

- Whisper on CPU was tested as a possible local transcription fallback, but it was not usable zero-shot for this dataset: it hallucinated Chinese output for an Iu Mien clip, so it is not a reliable path here.

- To keep moving without CUDA, we built a separate CPU-friendly supervised baseline in [train_wav2vec2_ctc_cpu.py](/Users/web/CAT/egs/IuMien/local/train_wav2vec2_ctc_cpu.py). That script reads the generated split files, builds a character vocabulary from Iu Mien transcripts, resamples audio to 16 kHz, trains on CPU, and saves checkpoints plus metrics.

- The tiny Wav2Vec2 smoke test succeeded, which confirmed that a local CPU training path is viable on this machine.

- The first `facebook/wav2vec2-base-960h` fine-tuning runs failed with `NaN` losses. We stabilized that path by lowering the learning rate, setting `grad-accum=1`, disabling spec augment by default, and adding an immediate failure check for non-finite loss in [train_wav2vec2_ctc_cpu.py](/Users/web/CAT/egs/IuMien/local/train_wav2vec2_ctc_cpu.py).

- The model load warnings were investigated and are expected rather than fatal:
  `wav2vec2.masked_spec_embed | MISSING` means a training-time parameter was initialized fresh,
  and `lm_head.weight` / `lm_head.bias | MISMATCH` means the CTC output layer was rebuilt for the Iu Mien label set instead of reusing the pretrained English output head.

- After stabilization, training became numerically healthy and losses decreased across runs and epochs, but `CER` and `WER` remained at `1.0`, so we added sample prediction logging to evaluation.

- That evaluation patch revealed the actual current failure mode: `dev_empty_pred_frac: 1.0`. The model is collapsing to CTC blank predictions, so all decoded hypotheses are empty even though the loss is improving.

- The current recommended next step is an unfrozen low-learning-rate run so the encoder has a better chance to escape blank-only decoding:
  `python local/train_wav2vec2_ctc_cpu.py --data-root /Users/web/MightLJSpeech/MightLJSpeech-1.1 --model facebook/wav2vec2-base-960h --save-dir exp_cpu/iumien_wav2vec2_unfrozen_200x5 --epochs 5 --max-train 200 --max-dev 50 --batch-size 1 --grad-accum 1 --lr 5e-6 --show-samples 5`
